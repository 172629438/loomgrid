# 迭代前必查 · 六类已发生过的问题

> 这份清单来自 2026-11-02 的 19 次修复。每一条都对应一次真实事故，
> 不是"可能的风险"，是"已经发生过的错误"。
>
> 写在这里的目的：**同一个坑不踩第二次。**

---

## 一、兜底逻辑只能有一份实现

**事故**：`d6598a13` — 导入 `2026年1月.xlsx` 报「未找到月份 '2026-01' 且资产 '2026'」。

**根因**：同一个概念（表号）在两个地方用了不同的兜底。

```
扫描阶段  _scan_wide_chunk    → 调用 _extract_asset_from_name()，拿不到时返回 '2026'
加载阶段  _load_group_data    → 写死 pd.Series('未命名')
```

两边一比对 `'未命名' == '2026'` 恒为 False，mask 全空，整表报未找到。

**规则**：**一个概念的默认值，只能有一个来源。** 扫描和加载共用一个函数，
不允许在任何一侧写死常量。

**自查**：`grep` 同一个语义的默认值（`'未命名'` / `'unknown'` / `0` / `''`），
出现两次以上就要合并。

## 二、正则兜底必须带反例排除

**事故**：同上。`_extract_asset_from_name()` 最后一条规则是：

```python
re.search(r'(\d{4,})', basename)      # 4 位以上数字就当表号
```

`2026年1月.xlsx` → 匹配到 **2026**，年份被当成表号。

**规则**：**任何"长得像"的匹配，都要列反例。**

```python
m = re.search(r'(\d{4,})', basename)
if m:
    v = int(m.group(1))
    if 1900 <= v <= 2100:            # 年份，不是表号
        return '未命名'
    return m.group(1)
```

**自查清单**——写提取规则时至少排除：
年份（1900–2100）、月份（1–12）、日期（1–31）、
纯序号（`001` / `002`）、文件大小与版本号。

## 三、修标准流要三个一起补

**事故**：`c07eec4a` — 打包后启动即报
`AttributeError: 'NoneType' object has no attribute 'isatty'`。

**根因**：frozen 环境（PyInstaller / cx_Freeze GUI 模式）下 `sys.stdin` 为 `None`。

**更早的事故**：`sys.stderr is None` 导致 loguru 抛 TypeError——
**当时只修了 stderr，没管 stdin/stdout。**

**规则**：**探测 `sys.std*` 的问题，三件一起补。**

```python
# import 之后立刻执行，全程序安全
if sys.stdin is None:
    sys.stdin = open(os.devnull, 'r', encoding='utf-8', errors='replace')
if sys.stdout is None:
    sys.stdout = open(os.devnull, 'w', encoding='utf-8', errors='replace')
if sys.stderr is None:
    sys.stderr = open(os.devnull, 'w', encoding='utf-8', errors='replace')
```

调用 `.isatty()` 处再包一层 `try`——某些冻结环境会抛 `ValueError` / `OSError`，
不该因为探测终端而阻止启动。

## 四、验证脚本必须分层，CI 要能跑

**事故**：CI 连续 6 次提交才跑通（`bc8f4630` → `6166eaf4`）。

**根因**：所有验证脚本都 `import` 主程序，而主程序 `import PySide6`。
CI 环境没有 GUI 依赖，全部失败。最后只能"只留三个不 import 主程序的脚本"。

**规则**：**验证脚本按依赖分三层，目录也要分开。**

```
tests/pure/        只依赖标准库 + numpy/pandas      → CI 必跑
tests/algo/        依赖算法层，不依赖 PySide6        → CI 必跑
tests/gui/         需要 Qt，只能本机跑               → CI 跳过
```

**判定方法**：`grep -L "PySide6" tests/*.py` 能列出所有可进 CI 的脚本。
如果一个"算法验证"脚本里出现了 Qt，那是**结构没解开**，不是 CI 的问题。

## 五、文档里的命令必须真跑过一遍

**事故**：`2f80f3cf` — `pip install loomgrid-algos` 之前是个**不存在的命令**。

**规则**：**写进 README 的每条命令，粘贴到终端里跑一次再提交。**

包括：安装命令、启动命令、验证命令、打包命令。
"应该能跑"不算，要真的跑出结果。

## 六、业务概念要在数据层就对齐

**事故**：
- `aaa6d8d7` — 充放电空间列按"方向"标注，但实际是按时段
- `4990ebf5` — 回头改成"每个时段一列"，不是"时段 × 方向"

**根因**：先写代码，再想概念。列的含义在实现过程中漂了两次。

**规则**：**动手前先用一句话定义清楚这个概念，写进代码注释。**

```
充放电空间 = 每个时段的可用能量上界与下界
           → 是「时段」维度，不是「时段 × 方向」
           → 一列 = 一个时段的净空间
```

如果一句话说不清，说明概念还没定型，不该开始写。

## 七、打包环境要写死在文档里

**事故**：本机默认 Python **3.14.5** 打出的 exe 启动即
`0xC0000005` ACCESS_VIOLATION（依赖不缺，是 PySide6 6.11.1 在 3.14
冻结环境下的兼容问题）。换 **3.12.13** 后正常，体积也小一半（286 MB vs 649 MB）。

**规则**：**打包用的 Python 版本写进 `tools/pack_release.py` 顶部的注释，
并在 README 的构建说明里点名。** 不能是"我这台机器上能打"。

## 每次迭代前的自查（打印出来贴在手边）

```
□ 同一个语义的默认值，只有一处实现？
□ 正则匹配有没有列反例（年份/序号/日期）？
□ sys.stdin / stdout / stderr 都补了吗？
□ 验证脚本分层了吗？CI 能跑的那层里有没有 Qt？
□ 文档里的命令，我真跑过吗？
□ 这次改动的概念，能用一句话说清吗？
□ 打包用的 Python 版本，写下来了吗？
```

---

**最后一条，也是最难的一条**：

**"我验证过了"和"它能用"是两件事。**

上面每一个事故，我都在本地跑通过。问题不在本地，在**别人的机器、
别人的数据、别人的打包环境**。所以验证的靶子要选对——
不是"我的测试过了"，而是"换一台机器、换一个文件，它还对不对"。
